A **routine** is a Python file with a `Config` class and an async `run` function. Condor runs it directly: it fetches data, computes what you asked for and returns a result or saves a report. No LLM reads the code or interprets the output while it runs, so the same input gives the same output and a run costs no tokens.

Use a routine for work you want done the same way every time: scans, indicators, price checks, bot summaries, backtest charts. Use a [skill](/trading-agents/architecture#skill-md) when the work needs judgment.

## Routines and skills

| | Skills | Routines |
|---|---|---|
| Format | `SKILL.md` instructions | Python file with `Config` and `run` |
| How it runs | The LLM reads it and decides what to do | Condor calls `run()` |
| Output | Varies with the model's reasoning | Same input, same output |
| Token cost | Tokens to read and follow it | None for the run itself |
| Good for | Approach, judgment, playbooks | Data work, indicators, reports, monitors |

## Where routines live

Who can run a routine depends on which folder it's in. `<condor>` is the folder you installed Condor into.

| Folder | Who can run it | Who writes it |
|---|---|---|
| `<condor>/routines/` | The Condor chat assistant, the Routines page and Telegram `/routines`. **Agents can't.** | Shipped with Condor. Condor's chat writes new routines here by default. |
| `<condor>/.condor/agents/_shared/routines/` | Condor chat **and every agent** | You, or Condor's chat when it publishes a routine as shared |
| `<condor>/agents/_shared/routines/` | Condor chat and every agent | Shipped with Condor |
| `<condor>/.condor/agents/<slug>/routines/` | That agent only | You, or the agent itself |
| `<condor>/agents/<slug>/routines/` | That agent only | Shipped with Condor |

<Tip>
To give a routine to every agent, put it in `.condor/agents/_shared/routines/`. The `.condor/` folder is ignored by git, so `git pull` and `/update` leave it alone.
</Tip>

When two folders hold a routine with the same name, the more specific one wins:

- An agent's own routine shadows a shared routine with the same name.
- For the chat, a routine in the top-level `routines/` shadows a shared one.
- A routine in `.condor/agents/` shadows the shipped copy in `agents/`.

To change a shared routine for one agent only, create a routine with the same name in that agent's `routines/` folder. See [Architecture](/trading-agents/architecture) for how agent folders work.

## A minimal routine

```python
from pydantic import BaseModel, Field
from telegram.ext import ContextTypes

from config_manager import get_client


class Config(BaseModel):
    """Show the current price of a few pairs."""

    connector: str = Field(default="binance", description="Exchange connector")
    pairs: list[str] = Field(
        default=["BTC-USDT", "ETH-USDT"], description="Trading pairs"
    )


async def run(config: Config, context: ContextTypes.DEFAULT_TYPE) -> str:
    chat_id = getattr(context, "_chat_id", None)
    client = await get_client(chat_id, context=context)
    if not client:
        return "No server available"

    result = await client.market_data.get_prices(
        connector_name=config.connector, trading_pairs=config.pairs
    )
    prices = result["prices"]
    lines = [f"{pair}: {price:,.2f}" for pair, price in prices.items()]
    return "\n".join(lines)
```

- **The file name is the routine's name.** Save this as `price_check.py` and it appears as `price_check`.
- **The first line of the `Config` docstring is the routine's description.** It shows on the routine's card and in the list agents see.
- **Each `Field(description=...)` labels a setting** in the dashboard config form and in Telegram.
- **`get_client(chat_id, context=context)`** returns a Hummingbot API client for the server the run was started on.

<Warning>
Never put an API key, password or private key in a `Config` default. Routine definitions are visible to every user of the install, and Condor refuses to load a routine whose defaults look like a credential. Read secrets inside `run()` from the environment instead.
</Warning>

## What `run` returns

`run(config, context)` can return either:

- **A string.** Shown in Telegram and in the dashboard's **Output** view.
- **A `RoutineResult`.** It has a `text` field for Telegram and optional fields the dashboard renders: `table_data` and `table_columns`, a `chart_image` (PNG bytes) and `sections`.

```python
from routines.base import RoutineResult
```

A routine can also save an HTML report with charts and tables. See [Reports](/routines/reports).

## One-shot and continuous routines

- **One-shot** routines run once and return. You can run them on demand or on a schedule.
- **Continuous** routines set `CONTINUOUS = True` at module level. They loop until you stop them, and they handle their own timing with `asyncio.sleep`. When stopped, Condor cancels the task, so catch `asyncio.CancelledError` and return a closing message. Continuous routines can't be scheduled.

The shipped `price_monitor` routine is continuous. It keeps a [live report](/routines/reports#live-reports) up to date while it runs. [Creating Routines](/routines/creating-routines#continuous-routines) has a full example.

## Optional module attributes

| Attribute | What it does |
|---|---|
| `CONTINUOUS = True` | Marks the routine as continuous |
| `CATEGORY = "Market Data"` | Category label. Defaults to `Uncategorized` for general routines and to the agent's name for an agent's routines. |
| `handle_callback(update, context, action, params)` | Telegram only. Async handler for inline buttons whose callback data is `routines:<routine_name>:<action>:...` |
| `MESSAGE_STATES` and `handle_message(update, context)` | Telegram only. When the chat's `routines_state` is one of the listed states, typed replies go to `handle_message` |
| `cleanup(context, instance_id, chat_id)` | Telegram only. Async hook called when you stop an instance from `/routines` |

## Running routines

| Where | How |
|---|---|
| **Dashboard** | The [Routines page](/webui/routines): pick a routine, set its config, then **Run** or **Schedule** |
| **Telegram** | `/routines`: pick a routine, edit its config, then **Run**, **Background**, **Schedule** or **Start** |
| **Chat** | Ask Condor to run it, for example *"run market_scanner with top_n=50"* |
| **Agents** | An agent calls `manage_routines(action="run", name=..., config={...})` on its tick |

When an agent runs a loop, its prompt lists every routine it can run, with each routine's description. A **Dry Run** refuses routine runs, because a routine can run any Python. Listing routines and reading their source still work.

## No restart needed

Condor checks the routine folders each time it lists routines, and reloads only files whose modification time changed. A new or edited file shows up the next time you open the Routines page, open `/routines` in Telegram, or an agent lists its routines.

Telegram's **🔄 Reload** button forces a full reload. Use it to retry a file that failed to load.

## Let Condor write routines

You can describe a routine in the chat and Condor writes it, loads it and runs it to test it:

```text
Create a routine that checks funding rates on binance_perpetual for the
top 20 pairs by volume and lists any rate above 0.01%.
```

Condor saves routines it writes to the top-level `routines/` folder. To make one available to every agent, ask Condor to publish it as **shared**, which saves it to `.condor/agents/_shared/routines/`. An agent that writes a routine saves it to its own `routines/` folder.
