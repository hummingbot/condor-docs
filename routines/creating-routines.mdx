This page walks through writing a one-shot routine and a continuous one, then using a routine from an agent.

**Before you start:** Condor is installed and connected to a Hummingbot API server. You can open the [Routines page](/webui/routines) or use `/routines` in Telegram.

## What a routine needs

| Part | Required | What it is |
|---|---|---|
| `Config` | Yes | A Pydantic `BaseModel`. Its fields are the routine's settings. The first line of its docstring is the description. |
| `run(config, context)` | Yes | An async function that returns a `str` or a `RoutineResult` |
| `CONTINUOUS = True` | No | Makes the routine loop until stopped |
| `CATEGORY` | No | A category label for the Routines page |

Telegram-only hooks (`handle_callback`, `handle_message`, `MESSAGE_STATES`, `cleanup`) are listed in the [overview](/routines/overview#optional-module-attributes).

## 1. Choose the folder

| Who should run it | Folder |
|---|---|
| Condor chat and every agent | `.condor/agents/_shared/routines/` |
| One agent | `.condor/agents/<slug>/routines/` |
| Condor chat only | `routines/` |

All paths are relative to the folder you installed Condor into. Create the folder if it doesn't exist. File names must be valid Python module names, such as `momentum_scanner.py`. Files that start with `_` are skipped in agent and shared folders.

## 2. Write the routine

This routine measures momentum and volume on recent candles for a few pairs. It returns a `RoutineResult`, so the dashboard shows a table and Telegram shows the one-line summary.

```python
from pydantic import BaseModel, Field
from telegram.ext import ContextTypes

from config_manager import get_client
from routines.base import RoutineResult

CATEGORY = "Market Data"


class Config(BaseModel):
    """Measure momentum and volume surge on recent candles."""

    connector: str = Field(default="binance", description="Exchange connector")
    pairs: list[str] = Field(
        default=["BTC-USDT", "ETH-USDT", "SOL-USDT"], description="Trading pairs"
    )
    interval: str = Field(default="5m", description="Candle interval")
    lookback: int = Field(default=24, description="Number of candles")


async def run(config: Config, context: ContextTypes.DEFAULT_TYPE) -> RoutineResult:
    chat_id = getattr(context, "_chat_id", None)
    client = await get_client(chat_id, context=context)
    if not client:
        return RoutineResult(text="No server available")

    rows = []
    for pair in config.pairs:
        candles = await client.market_data.get_candles(
            connector_name=config.connector,
            trading_pair=pair,
            interval=config.interval,
            max_records=config.lookback,
        )
        if isinstance(candles, dict):
            candles = candles.get("data", [])
        if len(candles) < 2:
            continue

        closes = [float(c["close"]) for c in candles]
        volumes = [float(c["volume"]) for c in candles]
        momentum = (closes[-1] - closes[0]) / closes[0] * 100
        surge = volumes[-1] > 1.5 * sum(volumes) / len(volumes)
        rows.append(
            {
                "pair": pair,
                "price": round(closes[-1], 4),
                "momentum_pct": round(momentum, 2),
                "volume_surge": "yes" if surge else "no",
            }
        )

    if not rows:
        return RoutineResult(text="No candle data returned")

    best = max(rows, key=lambda r: abs(r["momentum_pct"]))
    return RoutineResult(
        text=f"Strongest move: {best['pair']} {best['momentum_pct']:+.2f}%",
        table_data=rows,
        table_columns=["pair", "price", "momentum_pct", "volume_surge"],
    )
```

A few things to know about the API client:

- `get_candles` takes `max_records`, not `limit`. The server returns a list of candles, each with `timestamp`, `open`, `high`, `low`, `close`, `volume` and `quote_asset_volume`.
- `get_prices` returns `{"connector": ..., "prices": {"BTC-USDT": 81714.0, ...}, "timestamp": ...}`. Read the prices from `result["prices"]`.

## 3. Test it

Condor picks up the file without a restart. Then run it from any of these:

- **Dashboard:** open **Routines**, select `momentum scanner`, open **Config** to change settings, and click **Run**. Switch to **Output** to see the table.
- **Telegram:** `/routines` → **⚡ Momentum Scanner** → **▶️ Run**. Send `key=value` lines, such as `lookback=48`, to change the config first. Telegram lists only the general and shared routines, so a routine in an agent's folder doesn't appear there.
- **Chat:** ask Condor *"run momentum_scanner with interval=1h"*.

If the routine doesn't appear, the file failed to load. Check Condor's log for `Failed to load routine` or `Failed to load agent routine`. In Telegram, **🔄 Reload** retries files that failed before.

<Warning>
Condor refuses to load a routine whose `Config` defaults or descriptions look like a credential, such as an API key or a password. Read secrets inside `run()` from the environment instead.
</Warning>

## 4. Use it from an agent

If the routine is in the agent's own `routines/` folder or in `_shared/routines/`, the agent can run it. When the agent runs a loop, its prompt lists the routine and tells it to call:

```text
manage_routines(action="run", name="momentum_scanner", agent="<slug>", config={...})
```

Name the routine in your `loop.md` so the agent knows when to use it:

```markdown
1. Run the momentum_scanner routine for SOL-USDT on 5m candles.
2. If momentum_pct is above 2 and volume_surge is "yes", consider a long.
3. Otherwise, wait.
```

A blocking `run` waits up to 120 seconds. A longer run keeps going in the background, and the agent reads the result later with `action="get_instance"`. A **Dry Run** refuses routine runs, so test the routine on its own first.

See [MCP Tools](/trading-agents/mcp-tools) for the agent tool list and [Architecture](/trading-agents/architecture) for how loops work.

<Note>
A routine that agents run has no Telegram chat behind it. Don't rely on `context.bot.send_message` to deliver results. Return a `RoutineResult` or save a [report](/routines/reports) instead.
</Note>

## Continuous routines

A continuous routine sets `CONTINUOUS = True` and loops until you stop it. Condor stops it by cancelling the task, so catch `asyncio.CancelledError` and return a summary.

This one checks a price every few seconds and rewrites a single [live report](/routines/reports#live-reports) each time:

```python
import asyncio
from datetime import datetime, timezone

from pydantic import BaseModel, Field
from telegram.ext import ContextTypes

from condor.reports import LiveReport
from config_manager import get_client

CONTINUOUS = True
CATEGORY = "Monitoring"


class Config(BaseModel):
    """Track one price in a live report until stopped."""

    connector: str = Field(default="binance", description="Exchange connector")
    trading_pair: str = Field(default="BTC-USDT", description="Trading pair")
    interval_sec: int = Field(default=10, description="Seconds between checks")


async def run(config: Config, context: ContextTypes.DEFAULT_TYPE) -> str:
    chat_id = getattr(context, "_chat_id", None)
    report = LiveReport(
        f"Price Ticker: {config.trading_pair}",
        source_name="price_ticker",
        tags=["live"],
    )
    history = []

    try:
        while True:
            client = await get_client(chat_id, context=context)
            result = await client.market_data.get_prices(
                connector_name=config.connector, trading_pairs=config.trading_pair
            )
            price = result["prices"].get(config.trading_pair)
            if price is not None:
                now = datetime.now(timezone.utc).strftime("%H:%M:%S")
                history.append({"time": now, "price": price})

                report.clear()
                report.builder.kpi("Price", f"{price:,.2f}")
                report.builder.kpi("Checks", str(len(history)))
                report.builder.table(history[-50:])
                await report.update()

            await asyncio.sleep(config.interval_sec)
    except asyncio.CancelledError:
        return f"Stopped after {len(history)} checks"
```

Start it with **Run** on the Routines page or **▶️ Start** in Telegram. Stop it from the **Runs** list on the Routines page, or with **⏹ Stop All** in Telegram. Continuous routines can't be scheduled.

## Let Condor write it

You can describe the routine in the chat instead:

```text
Create a routine that ranks the top 20 binance_perpetual pairs by 24h
volume and shows each pair's 1h ATR as a percent of price.
```

Condor writes the file with `manage_routines(action="create_routine")`, checks that it loads, and runs it to test it. It saves to `routines/` unless you ask for a shared routine, which goes to `.condor/agents/_shared/routines/`. An agent asked to write a routine saves it to its own `routines/` folder.

## Best practices

<AccordionGroup>
  <Accordion title="Keep routines deterministic">
    The same config and the same market data should give the same result. Put judgment in the agent's skills and loop instructions, not in the routine.
  </Accordion>
  <Accordion title="Return errors as results">
    Return a short message such as `"No server available"` when something expected is missing. An exception marks the run as failed and the dashboard shows the error.
  </Accordion>
  <Accordion title="Describe every field">
    The `Config` docstring and each `Field(description=...)` are what you, Condor and agents read to decide how to run the routine.
  </Accordion>
  <Accordion title="Keep routines read-only unless you mean it">
    A routine runs with the full API client. Nothing stops it from placing orders or deploying bots, so keep trading actions in the agent, where the risk engine checks them.
  </Accordion>
  <Accordion title="Handle cancellation in continuous routines">
    Catch `asyncio.CancelledError` around the loop and return a summary.
  </Accordion>
</AccordionGroup>
