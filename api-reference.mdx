## What is Hummingbot API?

**Hummingbot API** is a RESTful API server that provides programmatic access to [Hummingbot](https://hummingbot.org) exchange connectors and trading strategies. It is the execution layer under Condor, and it handles:

- **Data collection**: standardized access to order books, candles, balances and positions across many exchanges
- **Market access**: connectors to spot and perpetual exchanges, plus DEXs on Solana and EVM networks through [Gateway](/api-reference/gateway)
- **Trade execution**: place orders, manage positions and track fills
- **Bot management**: deploy and manage containerized bots for long-running strategies

## Base URL

```text
http://localhost:8000
```

The API listens on `127.0.0.1` only by default, so it is reachable from the machine it runs on and nowhere else. To reach it from another machine, you have two options:

- **Tailscale (recommended):** `make setup` asks whether to use Tailscale. See [Secure Remote Access with Tailscale](/getting-started/installing#secure-remote-access-with-tailscale).
- **`API_BIND`:** set `API_BIND` in the API's `.env` to the address to publish port 8000 on, then run `make deploy` again. Prefer a specific interface, such as your Tailscale IP, over `0.0.0.0`. Anyone who reaches this API can move your funds.

`API_BIND` applies to the Docker install (`make deploy`). For where every service binds, see [What binds where by default](/getting-started/installing#what-binds-where-by-default).

## Authentication

Every REST endpoint except three requires HTTP Basic authentication:

```bash
curl -u YOUR_USERNAME:YOUR_PASSWORD http://localhost:8000/accounts/
```

A missing or wrong username or password returns `401` with `{"detail": "Incorrect username or password"}`.

These three paths need no credentials:

| Path | What it returns |
|------|-----------------|
| `/` | The API's name, version and status |
| `/docs` | The API's own interactive Swagger UI |
| `/openapi.json` | The OpenAPI spec this reference is generated from |

The username and password are the `USERNAME` and `PASSWORD` that `make setup` asks for and writes to the API's `.env`. Condor keeps a copy for each server in its `config.yml` under `servers:`.

<Warning>
If `USERNAME` and `PASSWORD` are not set, the API does not refuse to start. It falls back to `admin` / `admin` (and `CONFIG_PASSWORD` to `a`) and logs a `SECURITY WARNING`. Anyone who can reach the API can then log in. Always run `make setup`, or set all three values in `.env`, before you start the API.
</Warning>

### WebSocket authentication

The API also streams data over two WebSocket endpoints. They are not in the OpenAPI spec, so they don't appear in the sidebar:

| Endpoint | Streams |
|----------|---------|
| `ws://localhost:8000/ws/market-data` | Candles, order book snapshots and trades |
| `ws://localhost:8000/ws/executors` | Executors, executor summary and logs, performance, positions and bot status |

A WebSocket handshake authenticates in one of two ways. Without either, the server answers `401` and never opens the socket.

- **`Authorization: Basic base64(username:password)`**: the same header the REST endpoints use. Use it from any client that can set headers.
- **The `hummingbot-auth` subprotocol**: browsers can't set headers on a WebSocket, so send the credentials as the second subprotocol, encoded as base64url. The server echoes `hummingbot-auth` back.

```javascript
const token = btoa("YOUR_USERNAME:YOUR_PASSWORD")
  .replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");
const ws = new WebSocket("ws://localhost:8000/ws/executors", ["hummingbot-auth", token]);
```

The server never reads credentials from the query string.

## API Routers

The tables below are a tour of the API's routers, with the endpoints you will reach for first. The sidebar has the complete reference for every endpoint, generated from the API's own OpenAPI spec.

### Accounts

Manage trading accounts, exchange credentials and Gateway wallets. For the Workspace and Telegram flows, see [Exchange Credentials](/getting-started/credentials).

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/accounts/` | GET | List all account names |
| `/accounts/{account_name}/credentials` | GET | List configured connectors for an account |
| `/accounts/add-account` | POST | Create a new account |
| `/accounts/delete-account` | POST | Delete an account |
| `/accounts/add-credential/{account_name}/{connector_name}` | POST | Add exchange credentials |
| `/accounts/delete-credential/{account_name}/{connector_name}` | POST | Remove exchange credentials |
| `/accounts/gateway/wallets` | GET | List Gateway wallets |
| `/accounts/gateway/add-wallet` | POST | Add a Gateway (DEX) wallet |
| `/accounts/gateway/wallet/set-default` | POST | Set the default wallet for a chain |
| `/accounts/gateway/{chain}/{address}` | DELETE | Remove a Gateway wallet |

### Performance

One interface for the performance of both bot controllers and executors. Pass `subject=controller` or `subject=executor`.

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/performance/latest` | GET | The latest performance row for each controller or executor |
| `/performance/history` | GET | Performance over time, with optional `start_time` and `end_time` |

```bash
curl -u YOUR_USERNAME:YOUR_PASSWORD \
  "http://localhost:8000/performance/latest?subject=executor&limit=10"
```

Filters belong to one subject. `bot_name` works only with `subject=controller`. `executor_id`, `executor_type`, `account_name`, `connector_name` and `trading_pair` work only with `subject=executor`. `controller_id` works with both. A filter sent with the wrong subject returns `400`.

## Response Format

**Success responses** return the requested data:

```json
["master_account"]
```

**Error responses** include a `detail` field:

```json
{
  "detail": "Incorrect username or password"
}
```

## Trying endpoints

The easiest place to try requests is the API's own Swagger UI at `http://localhost:8000/docs`, on the machine that runs the API. Click **Authorize** and enter your username and password.

Each endpoint page in this reference also has a playground. It sends requests straight from your browser to the server URL, `http://localhost:8000` by default. The API accepts browser requests only from pages served on `localhost` or `127.0.0.1`, so it rejects the playground on this site (a CORS error). A local preview of these docs (`npx mint@latest dev`, on `localhost:3000`) is allowed.

To let this site's playground through, add its origin to the API's `.env` as a JSON list, then run `make deploy` again:

```bash
CORS_ALLOW_ORIGINS='["https://condor.hummingbot.org"]'
```

Only add origins you trust. Any page on an allowed origin can call your API from your browser. `CORS_ALLOW_ORIGIN_REGEX` holds the default `localhost` rule; set it to an empty string to turn that rule off.
