**Scripts** are single-file Hummingbot strategies. A script is a Python file with a config class and a strategy class. It runs inside a bot container, like a controller, but it's one self-contained program rather than a component that the bot hosts.

<Warning>
Condor has no way to deploy a script. Telegram, the Workspace and the agent tools (`manage_bots`) only deploy controller configs. To run a script, call the Hummingbot API directly, as shown in [Deploying a script](#deploying-a-script).
</Warning>

## Scripts vs Controllers

| Aspect | Scripts | Controllers |
|--------|---------|-------------|
| **Shape** | One file: config class + strategy class | Config + controller class, hosted by a bot |
| **Several per bot** | No, one script per bot | Yes, several controllers per bot |
| **Deploy from Condor** | No (Hummingbot API only) | Yes (Workspace, Telegram, agents) |
| **Live config updates** | No | Yes, for fields marked updatable |
| **Best for** | Quick automation, experiments | Strategies you run and tune over time |

A controller bot is itself a script: the Hummingbot API deploys controllers by generating a config for the `v2_with_controllers.py` script.

## Example scripts

The [Hummingbot repository](https://github.com/hummingbot/hummingbot/tree/master/scripts) ships example scripts, including:

| Script | Description |
|--------|-------------|
| `simple_pmm` | Places a bid and an ask around the mid or last price and refreshes them on a timer |
| `simple_xemm` | Cross-exchange market making |
| `simple_vwap` | Buys or sells a target amount in slices, VWAP style |
| `v2_funding_rate_arb` | Funding-rate arbitrage across perpetual venues |

<Note>
The Hummingbot API mounts its own `bots/scripts` folder into each bot container, which replaces the scripts bundled in the image. Out of the box that folder holds only `v2_with_controllers.py`. Upload any other script before you deploy it (step 1 below).
</Note>

## Script structure

A script has a config class that subclasses `StrategyV2ConfigBase` and a strategy class that subclasses `StrategyV2Base`. The config's `script_file_name` ties a config file to its script, and `update_markets()` declares which connectors and pairs the bot needs.

```python
# scripts/mid_price_logger.py
import os

from pydantic import Field

from hummingbot.core.data_type.common import MarketDict
from hummingbot.strategy.strategy_v2_base import StrategyV2Base, StrategyV2ConfigBase


class MidPriceLoggerConfig(StrategyV2ConfigBase):
    script_file_name: str = os.path.basename(__file__)
    exchange: str = Field(default="binance_paper_trade")
    trading_pair: str = Field(default="SOL-USDT")

    def update_markets(self, markets: MarketDict) -> MarketDict:
        markets[self.exchange] = markets.get(self.exchange, set()) | {self.trading_pair}
        return markets


class MidPriceLogger(StrategyV2Base):
    def __init__(self, connectors, config: MidPriceLoggerConfig):
        super().__init__(connectors, config)
        self.config = config

    def on_tick(self):
        connector = self.connectors[self.config.exchange]
        mid_price = connector.get_mid_price(self.config.trading_pair)
        self.logger().info(f"{self.config.trading_pair} mid price: {mid_price}")
```

`on_tick()` runs on every clock tick (once per second by default). To place orders, call `self.buy(...)` or `self.sell(...)` with a connector name, trading pair, `Decimal` amount and an `OrderType` (from `hummingbot.core.data_type.common`). See `simple_pmm.py` in the Hummingbot repository for a full order-placing example.

If you override `on_stop()`, make it `async` and call `await super().on_stop()`, because the base class uses it to shut down executors and market data.

## Deploying a script

You need three things on the Hummingbot API server: the script, a script config, and a deploy call. All three are API calls.

<Steps>
  <Step title="Upload the script">
    `POST /scripts/{script_name}` saves `bots/scripts/{script_name}.py`. The body is JSON with the file's source in `content`:

    ```bash
    python3 -c 'import json,sys; print(json.dumps({"content": open(sys.argv[1]).read()}))' mid_price_logger.py \
      | curl -u YOUR_USERNAME:YOUR_PASSWORD -X POST http://localhost:8000/scripts/mid_price_logger \
          -H "Content-Type: application/json" -d @-
    ```
  </Step>
  <Step title="Save a script config">
    `POST /scripts/configs/{config_name}` saves `bots/conf/scripts/{config_name}.yml`. The config must include `script_file_name`, because that's how Hummingbot knows which script to run:

    ```bash
    curl -u YOUR_USERNAME:YOUR_PASSWORD -X POST http://localhost:8000/scripts/configs/mid_price_logger_sol \
      -H "Content-Type: application/json" \
      -d '{
        "script_file_name": "mid_price_logger.py",
        "exchange": "binance_paper_trade",
        "trading_pair": "SOL-USDT"
      }'
    ```
  </Step>
  <Step title="Deploy the bot">
    `POST /bot-orchestration/deploy-v2-script` starts a container that runs the config:

    ```bash
    curl -u YOUR_USERNAME:YOUR_PASSWORD -X POST http://localhost:8000/bot-orchestration/deploy-v2-script \
      -H "Content-Type: application/json" \
      -d '{
        "instance_name": "sol-logger",
        "credentials_profile": "master_account",
        "script_config": "mid_price_logger_sol.yml"
      }'
    ```

    | Field | Required | Meaning |
    |-------|----------|---------|
    | `instance_name` | Yes | Bot name. The API appends a timestamp and returns the full name as `unique_instance_name`. |
    | `credentials_profile` | Yes | Account whose exchange keys the bot uses. |
    | `script_config` | Yes, in practice | File name of the config in `bots/conf/scripts`. The bot reads the script to run from this file's `script_file_name`. |
    | `image` | No | Docker image. Defaults to `hummingbot/hummingbot:latest`. |
    | `headless` | No | Run the bot without its terminal UI. Defaults to `false`. |
    | `script` | No | Recorded in the bot-run history only. It doesn't choose the script. |
  </Step>
</Steps>

<Note>
Starting a bot from a script config requires the Hummingbot API's config password (`CONFIG_PASSWORD`) to be set. Without it the deploy fails with "Password not provided".
</Note>

To stop a script bot, call `POST /bot-orchestration/stop-and-archive-bot/{bot_name}` with the full bot name.

## When to use scripts

**Use scripts for:**
- Quick, self-contained automation
- Experiments and learning the Hummingbot framework

**Use controllers for:**
- Strategies you want to deploy and manage from Condor
- Running several strategies in one bot with shared drawdown limits
- Changing parameters while the bot runs
