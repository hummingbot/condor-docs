---
title: "Build Your First Agent"
description: "Ask Condor to build a trading agent for you, then test it with a Dry Run, a single live tick and a loop"
---

A Condor Agent is a folder that Condor reads: an `AGENT.md` that says who the agent is, plus optional loops, routines, skills and controllers. You don't have to write that folder yourself. Condor ships with an `agent_builder` skill that creates the agent for you from a conversation.

This guide walks through building a first agent from a description, testing it, and stopping it.

## What you need

<Steps>
  <Step title="Condor connected to a Hummingbot API server">
    Follow [Installing](/getting-started/installing). In the Workspace the server selector in the top bar shows a green dot when the server is reachable.
  </Step>
  <Step title="Exchange keys">
    Add them in **Settings → Keys and Wallets → Add API Key**, and start with a small balance. See [Exchange Credentials](/getting-started/credentials). The Workspace doesn't list testnet connectors such as `binance_perpetual_testnet`; those can only be added through the Hummingbot API directly.
  </Step>
  <Step title="A model">
    A new agent uses the model Condor is running on unless you ask for a different one. See [LLM Integration](/llm-integration).
  </Step>
</Steps>

## 1. Ask Condor to build it

Open the Workspace and talk to **Condor** in the chat. In Telegram, send Condor a plain message; if you switched to another agent earlier, send `/agent`, tap **Talk to** and choose **Condor (coordinator)**.

Describe the agent in a sentence or two: what it specializes in and what you will use it for. For example:

```text
Build me an agent that specializes in SOL-USDT perpetuals on support and
resistance levels. I want to ask it for trade setups, and later let it
open and close position executors on its own.
```

Condor follows the [Agent Builder](/condor-agent/agent-builder) skill. It starts small and adds one piece at a time, asking you before each step:

1. **Creates the agent.** It settles the agent's role and what it is for, then writes its `AGENT.md`.
2. **Asks it a question** in its specialty and shows you the answer, to prove it works. If the answer is off, Condor edits the instructions and asks again.
3. **Adds routines,** if you want them. A routine is deterministic Python that turns raw market data into the view the agent needs, such as a support and resistance scan. Condor hands each routine to a background worker, which writes and tests it. The work appears in the **Tasks** panel beside the chat.
4. **Writes a loop,** if you want the agent to act on its own. The loop is the playbook it follows on every tick, with its frequency and risk limits.

The agent can answer questions as soon as step 1 is done. Routines and a loop make it more specific; they aren't required.

<Tip>
If you already have controllers, configs or strategy notes in a folder, give Condor the folder's path instead. The skill reads every file, proposes a build plan, and writes nothing until you approve it. See [Build from a folder](/condor-agent/agent-builder#path-b-build-from-a-folder).
</Tip>

## 2. Find what it built

Condor writes the agent under the local agents folder of your Condor install:

```text
.condor/agents/<slug>/
  AGENT.md                 # identity, model, tools
  loops/<loop>/loop.md     # per-tick playbook, if you asked for a loop
  routines/<name>.py       # if you asked for routines
```

The slug is the agent's name in lowercase with spaces turned into underscores, for example `sol_sr_scalper`. Open `/agents/<slug>` in the Workspace to see the agent page. From the chat you can also open the agent's panel and click **Workspace**.

<Note>
**Where to put your agent.** Agents you create belong in `.condor/agents/`, which `git pull` and `/update` never touch. The `agents/` folder in the repo holds the agents that ship with Condor. See [Architecture](/trading-agents/architecture#where-condor-looks-for-agents) for the full folder layout and file formats.
</Note>

Before you test, check two things the builder can get wrong:

- **Routines.** Open **Routines** in the top bar and check that the new routine is listed under your agent. A background worker can save it to Condor's general library instead, where the agent can't run it. If so, ask Condor to move it into the agent's routines.
- **Tools.** If the agent's `tools` list is not empty, make sure it includes `get_market_data`. It is the candle tool that also works in a Dry Run, and a tool left off the list is never available to the agent. An empty list means the agent can use every tool.

## 3. Test it

On the agent page, pick the loop in the selector under the agent's name, click **Start**, and work through the three execution modes in order.

<Frame>
  <img src="/images/webui/agent-start-dry-run.jpg" alt="The Start New Session dialog with Dry Run selected and the Run Dry Test button" />
</Frame>

<Steps>
  <Step title="Dry Run">
    Choose **Dry Run**, enter the pair and exchange in **Trading Context** (for example `Trade SOL-USDT on binance_perpetual`), and click **Run Dry Test**. The agent runs one tick in which every action that would change something is refused. Open the **Runs** tab to read what it did and what it decided.

    <Note>
    A Dry Run also refuses routines and `run_code`, so the agent can't run its own analysis. It reads the market with read-only tools such as `get_market_data` instead. Use the Dry Run to check that the agent, server and exchange are wired up and that its reasoning makes sense, not to judge the strategy.
    </Note>
  </Step>
  <Step title="Run Once">
    Choose **Run Once** and click **Execute Once**. This runs one live tick: the agent can open real executors or deploy a real bot, so use small capital. Check the **Runs** and **Fleet** tabs afterwards.
  </Step>
  <Step title="Loop">
    When that tick looks right, start again with **Loop** and click **Start Session**. Set **Total Amount Quote**, **Frequency (sec)** and the risk limits (**Max Position ($)**, **Max Executors**, **Max Drawdown %**) to amounts you would accept losing.
  </Step>
</Steps>

<Frame>
  <img src="/images/webui/agent-runs.jpg" alt="The Runs tab of the Market Making Expert, showing a dry run's agent response" />
</Frame>

You can also ask Condor in chat to start the loop. Starting a loop always needs your approval: the Workspace shows an approval card with **Allow** and **Deny**, and Telegram shows a confirmation.

## 4. Watch and stop it

The agent page has four tabs:

| Tab | What it shows |
|---|---|
| **Now** | The last decision and what the session has deployed |
| **Runs** | Every session and dry run, with each tick's prompt, tool calls and response |
| **Fleet** | The bots and executors this session owns |
| **Playbook** | The loop's `loop.md` and its learnings. You can edit both here. |

To stop it:

| You want to | Do this |
|---|---|
| Pause decisions but keep everything running | **Pause** on the agent page; **Resume** to continue |
| End the loop | **Stop** on the agent page, then **Confirm** |
| Wind everything down now | Ask the agent in chat to shut its loop down |

<Warning>
**Stop** ends the loop but leaves its executors, positions and bots open, and nothing manages them until you start the same loop again, which adopts what was left. Close them yourself, or use a shutdown, which closes them according to the agent's `shutdown.md` policy. See [Stopping a loop](/trading-agents/architecture#stopping-a-loop).
</Warning>

## Write the folder by hand instead

You can skip the builder and create the files yourself: an `AGENT.md` in `.condor/agents/<slug>/` and, optionally, `loops/<loop>/loop.md`. Reload the Workspace and the agent appears. [Architecture](/trading-agents/architecture#creating-your-own-agent) has the file formats, the frontmatter fields and the risk limits.
