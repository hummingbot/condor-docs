---
title: "Configuring Condor"
description: "Every environment variable Condor reads, what it defaults to, and when you would change it"
---

Condor is configured in two places. **`.env`** holds the settings below, and
**`config.yml`** holds servers, users, permissions, preferences and chat defaults — written
by `make setup` and by `/servers`, not by hand.

Almost nothing here needs setting. The install wizard writes what a working
install requires, and the rest exist for operators with a specific reason.

<Note>
  After editing `.env`, restart Condor for it to take effect — `make restart`.
  `make doctor` re-reads it and reports what the running install would see.
</Note>

## Identity and mode

| Variable | Default | What it does |
|----------|---------|--------------|
| `CONDOR_MODE` | `telegram` | `telegram` or `local`. Never inferred from whether a token is present — an install whose token went missing fails at boot rather than quietly becoming an unauthenticated Workspace. See [Choosing Telegram or Local mode](/getting-started/installing#choose-your-install) |
| `TELEGRAM_TOKEN` | — | Bot token from [@BotFather](https://t.me/botfather). Required unless `CONDOR_MODE=local` |
| `ADMIN_USER_ID` | — | Your numeric Telegram user id, and the id Local mode logs in as. Everything — servers, preferences, memory, chat defaults — is keyed to it. In Local mode, `make setup` keeps an existing id, or writes `1` if there is none |

## Workspace

| Variable | Default | What it does |
|----------|---------|--------------|
| `WEB_URL` | `http://localhost:<WEB_PORT>` | The address `/web` links point to. **It also sets the port the Workspace listens on**, and it wins over `WEB_PORT`. With no port in the URL, Condor listens on `443` for `https://` or `80` for `http://`. `make setup` writes it: `http://localhost:8088` in Local mode; in Telegram mode, the public address you enter or the tailnet address when Tailscale is on |
| `WEB_PORT` | `8088` | The port the Workspace listens on. Used only when `WEB_URL` is not set |
| `WEB_HOST` | Local mode: `127.0.0.1`. Telegram mode: `0.0.0.0`, or the tailnet address with `USE_TAILSCALE=true` | Which interface the Workspace binds. Setting it overrides every default, so read [What binds where by default](/getting-started/installing#what-binds-where-by-default) before changing it |
| `WEB_JWT_SECRET` | generated, stored in `config.yml` | Signs Workspace login tokens. Set it explicitly to keep sessions valid across instances, or to hold the secret outside `config.yml` |
| `USE_TAILSCALE` | unset | In Telegram mode, `true` binds the Workspace to this machine's tailnet address, so it is reachable on your tailnet and on no public interface. In Local mode it has no effect on the Workspace, which stays on `127.0.0.1` |
| `VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY` | generated on first use, stored in `data/push_keys/` | The key pair for [browser notifications](/webui/settings#notifications). Set both or neither, only if you manage the keys yourself. Changing the keys stops every existing device subscription from working |
| `VAPID_SUBJECT` | `mailto:condor@localhost` | Contact address sent to browser push services. Must be a `mailto:` or `https:` URL |

<Warning>
  Because `WEB_URL` sets the listening port, `WEB_URL=https://dashboard.example.com` makes Condor itself try to listen on port 443. See [Change the Workspace address](/getting-started/web-dashboard#change-the-workspace-address) before putting a reverse proxy in front.
</Warning>

## Privacy

Both are the operator-level kill switches. They override anything chosen in the
Workspace, and neither needs to be set on a fresh install — see
[Privacy: telemetry and sharing](/getting-started/privacy).

| Variable | Default | What it does |
|----------|---------|--------------|
| `CONDOR_TELEMETRY` | unset | `off` disables telemetry and suppresses the notice. `ping` or `usage` sets the level. Either way it overrides what is stored, including a refusal made in the Workspace. Unset, telemetry follows the notice and **Settings → Privacy** |
| `CONDOR_SHARING` | unset | `off` stops any conversation leaving, and destroys anything already queued. A queued *unshare* is still delivered — a revocation is a deletion the install already promised |

## Updates

| Variable | Default | What it does |
|----------|---------|--------------|
| `UPDATE_CHECK_INTERVAL` | `3600` | Seconds between background update checks. `0` disables them. The first check runs 30 seconds after startup — see [Keeping Condor updated](/getting-started/updating) |

## AI models

How to choose and set up a model is covered in [LLM Integration](/llm-integration). These are the variables it uses:

| Variable | Default | What it does |
|----------|---------|--------------|
| `CONDOR_DEFAULT_AGENT` | set by `make pick-model` | The model Condor uses when you haven't picked one in a chat. `make pick-model` writes it and checks the model is reachable. See [The default model](/llm-integration#the-default-model) |
| `OPENROUTER_API_KEY` | unset | Needed for `openrouter:` models. See [OpenRouter](/llm-integration#openrouter) |
| `CUSTOM_LLM_BASE_URL`, `CUSTOM_LLM_API_KEY` | unset | A custom OpenAI-compatible endpoint to use when none is saved in the Workspace. See [Custom endpoints](/llm-integration#custom-openai-compatible-endpoints) |
| `CUSTOM_LLM_BLOCK_PRIVATE_URLS` | unset | `true` refuses custom endpoints on `localhost` or a private network. Turn it on for a Condor shared by several users |
| `CONDOR_DEFAULT_LOCAL_MODEL`, `OLLAMA_MODEL` | unset | The model to use for a bare `ollama:` or `lmstudio:` key. `CONDOR_DEFAULT_LOCAL_MODEL` is checked first |
| `LMSTUDIO_BASE_URL` | unset | Base URL for local-server models in chat. See [Ollama and LM Studio](/llm-integration#ollama-and-lm-studio) for what else it affects |
| `LOCAL_MODEL_READ_TIMEOUT` | `600` | Seconds to wait for a reply from Ollama, LM Studio, OpenRouter or a custom endpoint |
| `AGENT_FALLBACK_MODEL` | `claude-code` | Used when an agent is asked for help and its own model's server is unreachable. Set it empty to turn the fallback off. See [Models for agents and loops](/llm-integration#models-for-agents-and-loops) |

## Market data

| Variable | Default | What it does |
|----------|---------|--------------|
| `COINGECKO_API_KEY` | unset | A paid CoinGecko API key. With it, pool and market data use CoinGecko's paid API and a higher rate limit. Without it, Condor uses the free public API. If the paid API rejects the key, Condor goes back to the public API |

## Retention and limits

Every one of these has a working default. They exist for installs where disk,
history depth or context size needs a different answer.

| Variable | Default | What it does |
|----------|---------|--------------|
| `CONDOR_BACKTEST_RETENTION_DAYS` | `30` | How long backtest payloads are kept on disk |
| `CONDOR_RUN_HISTORY_RETENTION_DAYS` | `60` | How long run-history payloads are kept |
| `CONDOR_MAX_REPORTS` | `100` | Reports retained before the oldest are dropped |
| `CONDOR_MAX_DELEGATION_RECORDS` | `500` | Background delegation records retained |
| `CONDOR_MAX_CONSULT_RECORDS` | `300` | Records kept for questions one agent asks another (`delegate` asks). Kept separately from delegations |
| `CONDOR_TRANSCRIPT_MAX_BYTES` | `2097152` (2 MiB) | Transcript size that triggers a trim |
| `CONDOR_TRANSCRIPT_KEEP_BYTES` | `1048576` (1 MiB) | How much is kept when one is trimmed |
| `CONDOR_REPLAY_MAX_CHARS` | `6000` | Characters of replay context handed to a model |

<Warning>
  A retention value is a floor on what you can look back at later. Lowering one
  deletes history at the next sweep, and there is no undo — an over-small value
  is history that is gone for good.
</Warning>

## Storage locations

Where Condor keeps agents and runtime data. Each defaults to a folder inside your Condor install. See [Architecture](/trading-agents/architecture#where-condor-looks-for-agents) for how the two agent folders are merged.

| Variable | Default | What it does |
|----------|---------|--------------|
| `CONDOR_RUNTIME_ROOT` | `<condor>/.condor` | Everything Condor accumulates while running: local agents, sessions, memory, conversations |
| `CONDOR_AGENTS_ROOT` | `<condor>/.condor/agents` | Your own agents, and every change Condor makes to an agent |
| `CONDOR_STOCK_AGENTS_ROOT` | `<condor>/agents` | The agents that ship with Condor. Updates replace this folder |
| `CONDOR_DATA_DIR` | `<condor>/data` | Operational data: preferences, notifications, update records |
| `CONDOR_REPORTS_DIR` | `<condor>/reports` | Routine reports |

## Timeouts

Every deadline has a default that suits most installs. Override one with `CONDOR_TIMEOUT_<NAME>`, in seconds. A value that is not a number is ignored, with a warning in the log.

| Variable | Default | What it limits |
|----------|---------|----------------|
| `CONDOR_TIMEOUT_CONFIRMATION` | `120` | How long you have to answer an approval request before it is denied |
| `CONDOR_TIMEOUT_PROMPT_OVERALL` | `1800` | Total time for one chat reply |
| `CONDOR_TIMEOUT_PROMPT_QUEUE` | `900` | How long a queued message waits for its turn behind a reply in progress |
| `CONDOR_TIMEOUT_PROMPT_LOCK` | `30` | How long a message waits for a stuck previous reply before giving up |
| `CONDOR_TIMEOUT_TICK_DEFAULT` | `600` | One agent tick's model turn |
| `CONDOR_TIMEOUT_SESSION_IDLE` | `3600` | How long an unused chat session stays open before Condor detaches it. The conversation is kept. `0` turns this off |
| `CONDOR_TIMEOUT_AGENT_HANDSHAKE` | `120` | How long a model client may take to start and complete its handshake |
| `CONDOR_TIMEOUT_MCP_CALL` | `15` | One MCP tool call |

## Advanced

Rarely set, and listed so a value you find in someone's `.env` is not a mystery.

| Variable | Default | What it does |
|----------|---------|--------------|
| `CONDOR_PERSISTENCE_FILE` | `data/condor_bot_data.pickle` | Where the Telegram bot's session state is saved. Agent conversations and preferences are stored elsewhere |
| `CONDOR_RUNTIME_MODE` | `local` | Session-runtime transport. `http` is reserved for a future process split and is not implemented |
| `GATEWAY_URL` | unset | Condor does **not** reach Gateway through this — Gateway is configured in `hummingbot-api`'s own `.env` and driven via `/gateway`. Setting it here only flips a capability flag in telemetry |

## Environment overrides

Condor reads `.env` at startup, but a variable already set in the environment it starts from takes priority. That usually happens by accident. For example, a tmux server started from another project hands its own `TELEGRAM_TOKEN` to every window, and Condor then runs as that project's bot.

At startup, Condor logs a warning for each `.env` variable that the environment overrides. It names the variable, never the value. For `TELEGRAM_TOKEN` it also names both bot ids. To let `.env` win, start Condor where the variable is unset: `unset TELEGRAM_TOKEN`, or `tmux set-environment -gu TELEGRAM_TOKEN` for new tmux windows.

## Not in `.env`

Servers, their credentials, users, roles and per-chat defaults live in
`config.yml`, written by `make setup` and by `/servers`. The Hummingbot API's
own settings — `API_BIND`, `DB_BIND`, broker credentials, `GATEWAY_PASSPHRASE` —
live in `hummingbot-api/.env`, not here.
