Condor needs a language model for chat and for its agents. You can use a coding-agent CLI you already log in to, a cloud API key, or a model running on your own machine.

Condor reaches models in two ways:

- **ACP bridges**: Claude, Gemini, GitHub Copilot and Codex run as a separate process that speaks the [Agent Client Protocol](https://agentclientprotocol.com). You log in to each one once, with its own CLI.
- **OpenAI-compatible APIs**: OpenRouter, Ollama, LM Studio and custom endpoints are called directly by Condor. They need an API key, a running local server, or both.

## The model options

Every place that offers a model (the setup wizard, the dashboard pickers and Telegram) uses the same list:

| Label | Agent key | How it runs |
|---|---|---|
| Claude Code | `claude-code` | Claude ACP bridge, using the bridge's own default model |
| Claude (ACP) — Opus | `claude-acp:opus` | Claude ACP bridge, pinned to Opus |
| Claude (ACP) — Sonnet | `claude-acp:sonnet` | Claude ACP bridge, pinned to Sonnet |
| Claude (ACP) — Haiku | `claude-acp:haiku` | Claude ACP bridge, pinned to Haiku |
| Gemini CLI | `gemini` | `npx @google/gemini-cli --acp` |
| GitHub Copilot CLI | `copilot` | `npx @github/copilot --acp --stdio` |
| ChatGPT Codex | `codex` | `npx @agentclientprotocol/codex-acp` |
| Ollama — Default Model | `ollama:` or `ollama:<model>` | Ollama server, default `http://localhost:11434/v1` |
| LM Studio — Default Model | `lmstudio:` or `lmstudio:<model>` | LM Studio server, default `http://localhost:1234/v1` |
| OpenRouter — Pick Model | `openrouter:<slug>` | OpenRouter API. Opens a model list. |
| Custom — OpenAI-compatible API | `custom@<nickname>:<model>` | An endpoint you saved. Opens a model list. |

The two "Pick Model" rows aren't models. They open a list, and your choice is stored as the full key, for example `openrouter:deepseek/deepseek-v4.1-flash`.

### The default model

The recommended model is **Claude (ACP) — Sonnet** (`claude-acp:sonnet`). `make pick-model` lists it first.

When you haven't picked a model yourself, Condor uses the first of these that is set:

1. `CONDOR_DEFAULT_AGENT` in `.env`
2. The `agent_key` in Condor's own `agents/condor/AGENT.md`, which ships as `claude-acp:sonnet`
3. `claude-code`

A model you pick in Telegram or on the dashboard chat page overrides this default for your chats.

## Choose a model

<Tabs>
  <Tab title="make pick-model">
    Run this in the Condor folder:

    ```bash
    make pick-model
    ```

    It lists every option with a status for this machine: ready (✓), installed but login not confirmed (?), or not usable (✗) with the fix. Pick a number, and Condor saves it to `.env` as `CONDOR_DEFAULT_AGENT`.

    - If you pick a bridge that isn't installed, the wizard runs its `npm install -g` command for you.
    - If the Claude bridge is outdated and you pick a Claude option (or Claude is your default), the wizard runs the upgrade.
    - For Ollama or LM Studio, it lists the models the server has loaded. Press Enter to let the server choose at session start.
    - For OpenRouter, it asks for your API key, checks it with OpenRouter, and lists the 20 cheapest models that support tool calling. It saves the key to `.env` as well.
    - Custom endpoints aren't offered here. Add them from the dashboard or Telegram.

    Restart Condor (`make restart`) so the new default takes effect. To print the report without changing anything, run `uv run python -m condor.setup_llm --status`. `make doctor` also checks the default model.
  </Tab>
  <Tab title="Dashboard">
    - **Chat:** the model picker sits above the message box when you start a new chat.
    - **Agent page:** the agent's model is shown next to its name. Click it to change the model the agent uses everywhere it runs. This writes `agent_key` into the agent's `AGENT.md`.

    Both pickers grey out options this machine can't run and show why, such as "not installed — npm install -g …". Saved custom endpoints appear in their own section.
  </Tab>
  <Tab title="Telegram">
    Send `/agent` and tap **Change LLM**, then pick a model. Condor replies:

    ```text
    LLM set to <label>. New sessions will use this model.
    ```

    Picking a model ends the current session, so your next message starts a new one on the new model. Options this machine can't run are marked ⚠️. You can still pick them, for example before you start `ollama serve`, and Condor tells you what is missing.

    The `/agent` menu also has **Start**, **Talk to** and **Conversations**. While a session is running it shows **New**, **Compact** and **End session**.
  </Tab>
</Tabs>

## Claude

Condor runs Claude through the `claude-agent-acp` bridge from the npm package `@agentclientprotocol/claude-agent-acp`.

<Steps>
  <Step title="Install the bridge">
    ```bash
    npm install -g @agentclientprotocol/claude-agent-acp
    ```
  </Step>
  <Step title="Log in once">
    Run `claude` and log in to your Anthropic account. Condor checks for the login in `~/.claude/.credentials.json` (or the macOS keychain). See the [Claude Code docs](https://docs.claude.com/en/docs/claude-code/overview) to install the `claude` CLI.
  </Step>
  <Step title="Pick a Claude option">
    Choose **Claude (ACP) — Sonnet**, **Opus** or **Haiku** to pin a model, or **Claude Code** to use the bridge's own default model.
  </Step>
</Steps>

<Warning>
**The bridge must be version 0.79.0 or newer.** The older package `@zed-industries/claude-agent-acp` still launches, but it is frozen at 0.23. Its bundled Claude CLI bills Sonnet 4.6 at Opus rates and doesn't know any model newer than the 4.6 family.

`make pick-model` and `make doctor` mark an old bridge as outdated and show the fix. `make pick-model` runs the upgrade when you choose a Claude option or when Claude is already your default, and a Condor update (`/update`) upgrades it automatically. To do it by hand:

```bash
npm uninstall -g @zed-industries/claude-agent-acp
npm install -g @agentclientprotocol/claude-agent-acp@latest
```

The uninstall is needed because both packages install the same `claude-agent-acp` command.
</Warning>

## Gemini, GitHub Copilot and Codex

Condor launches these bridges with `npx`, but it treats a bridge as installed only when its npm package is already on disk. Install each one globally:

| Option | Install | Log in once |
|---|---|---|
| Gemini CLI | `npm install -g @google/gemini-cli` | Run `npx @google/gemini-cli` and log in, or set `GEMINI_API_KEY` |
| GitHub Copilot CLI | `npm install -g @github/copilot` | Run `npx @github/copilot` and log in |
| ChatGPT Codex | `npm install -g @agentclientprotocol/codex-acp` | Run `codex` and log in |

Condor checks for a Gemini login in `~/.gemini/oauth_creds.json` (or `GEMINI_API_KEY`) and a Codex login in `~/.codex/auth.json`. It can't check a Copilot login, so Copilot shows as "login could not be verified" until your first chat works.

**Updating Codex.** If a newer Codex model fails because the bridge is outdated, run:

```bash
make refresh-codex
```

This updates `@agentclientprotocol/codex-acp` and the Codex CLI bundled with it. Start a new Codex session afterwards. Sessions that are already running keep the old bridge.

## OpenRouter

OpenRouter gives you many models through one API key. Condor lists only OpenRouter models that support tool calling, because its agents depend on tools.

1. Create a key at [openrouter.ai/keys](https://openrouter.ai/keys).
2. Add it to Condor's `.env`, or let `make pick-model` save it for you:

   ```bash
   OPENROUTER_API_KEY=sk-or-...
   ```

3. Pick a model:
   - **Dashboard:** choose **OpenRouter — Pick Model** in the model picker.
   - **Telegram:** `/agent` → **Change LLM** → **OpenRouter — Pick Model**. Page through the list, or tap **Enter model manually** and send a slug.
   - **`make pick-model`:** choose OpenRouter.

The model is stored as `openrouter:<slug>`, for example `openrouter:deepseek/deepseek-v4.1-flash`. You can browse the list without a key, but a session can't start until `OPENROUTER_API_KEY` is set.

## Ollama and LM Studio

Local models run on your own machine with no API cost.

<Tabs>
  <Tab title="Ollama">
    1. Install Ollama from [ollama.com](https://ollama.com) and start it with `ollama serve`.
    2. Pull a model, for example `ollama pull qwen3:32b`.
    3. Choose **Ollama — Default Model**, or set a specific model as `ollama:<model>`, for example `ollama:qwen3:32b`.

    Condor connects to `http://localhost:11434/v1`.
  </Tab>
  <Tab title="LM Studio">
    1. Install LM Studio from [lmstudio.ai](https://lmstudio.ai), load a model and enable its local server.
    2. Choose **LM Studio — Default Model**, or set a specific model as `lmstudio:<model>`.

    Condor connects to `http://localhost:1234/v1`.
  </Tab>
</Tabs>

**Which model the default option uses.** With a bare key (`ollama:` or `lmstudio:`), Condor picks the model when the session starts:

1. `CONDOR_DEFAULT_LOCAL_MODEL` or `OLLAMA_MODEL`, if either is set
2. Otherwise the first model the server lists at `/v1/models`
3. For Ollama only, the first model from `/api/tags`

If none of these finds a model, the session fails with "No local model found". Use an explicit key such as `ollama:qwen3:32b`, or set `CONDOR_DEFAULT_LOCAL_MODEL`.

**Server on another address.** For a local server on a different host or port, the simplest option is to add it as a [custom endpoint](#custom-openai-compatible-endpoints). Chat sessions also read `LMSTUDIO_BASE_URL` from `.env` as their base URL for these models. Set it only when you use LM Studio: Condor applies it to every model of this kind in chat, including Ollama and OpenRouter, unless you choose a custom endpoint.

**Slow first replies.** A local model can take a long time to load on its first request. Condor waits up to 600 seconds for a reply. Set `LOCAL_MODEL_READ_TIMEOUT` (in seconds) to change this.

## Custom OpenAI-compatible endpoints

You can connect any API that follows the OpenAI format, such as Venice AI, Together, Fireworks, or your own vLLM or LM Studio server. Endpoints are saved per user, and the dashboard and Telegram share the same list.

<Tabs>
  <Tab title="Dashboard">
    1. Open **Settings → LLM Endpoints** and click **Add endpoint**.
    2. Enter the **Base URL**, for example `https://api.venice.ai/api/v1`.
    3. Enter an **API key**, or leave it blank if the endpoint doesn't need one.
    4. Optionally enter a **Name**. If you leave it blank, Condor derives one from the URL.
    5. Click **Validate & save**.
  </Tab>
  <Tab title="Telegram">
    1. Send `/agent` → **Change LLM** → **Custom — OpenAI-compatible API** → **+ Add endpoint**.
    2. Send the base URL as a message.
    3. Send the API key as a message, or tap **No API key needed**. Condor deletes the message that contains your key.
  </Tab>
</Tabs>

Condor checks the endpoint by fetching `<base URL>/models` and lists the chat models it finds. Pick one, and Condor stores it as `custom@<nickname>:<model>`, for example `custom@venice:llama-3.3-70b`.

Optional `.env` variables:

```bash
CUSTOM_LLM_BASE_URL=https://api.venice.ai/api/v1   # Used when no endpoint is saved in the UI
CUSTOM_LLM_API_KEY=sk-...
CUSTOM_LLM_BLOCK_PRIVATE_URLS=true                 # Refuse localhost and private-network URLs
```

Leave `CUSTOM_LLM_BLOCK_PRIVATE_URLS` unset on a personal install, so you can point at a server such as `http://localhost:8000/v1`. Turn it on for a Condor shared by several users. Cloud metadata addresses are always refused.

## Models for agents and loops

Each agent has its own model, set by `agent_key` in its `AGENT.md`. Most shipped agents use `claude-acp:sonnet`, and a new agent starts with the model you're using. If `agent_key` is empty, a chat with that agent uses your chat's model, but its loops and delegations run on `claude-code`.

```yaml
---
name: Market Making Expert
agent_key: claude-acp:sonnet
---
```

You can change it from the agent page (the model next to its name), or by editing `AGENT.md`.

A loop run picks its model in this order:

1. `agent_key` in the run's config
2. `agent_key` in the loop's `loop.md` (`null` means "use the agent's model")
3. The agent's `agent_key`

**A loop won't start on a model that can't run.** Before it starts a loop, Condor checks the model and refuses with `Model '<key>' cannot run: <reason>`. Examples are an unknown provider, a key with no model id, a custom endpoint you never saved, or an OpenRouter model without `OPENROUTER_API_KEY`. A local server that is switched off isn't caught by this check, because it may be running by the first tick. That fails at run time instead.

**Fallback when an agent is asked for help.** When one agent delegates to another whose model is Ollama, LM Studio, OpenRouter or a custom endpoint, Condor first checks that backend. If it is unreachable, Condor answers with `AGENT_FALLBACK_MODEL` instead (default `claude-code`) and notes this in the answer. Set `AGENT_FALLBACK_MODEL=` (empty) in `.env` to turn the fallback off, so the request fails with the reason instead.

## Troubleshooting

<AccordionGroup>
  <Accordion title="An option is greyed out or marked ⚠️">
    Run `make pick-model` or `make doctor`. Each row says what is missing and the command that fixes it, for example `not installed — npm install -g @github/copilot` or `not reachable at http://localhost:11434/v1 — start it with ollama serve`.
  </Accordion>
  <Accordion title="A bridge is installed but the first chat fails">
    The bridge needs its own login. Run the login command from the [Gemini, GitHub Copilot and Codex](#gemini-github-copilot-and-codex) table, or `claude` for Claude, then start a new session.
  </Accordion>
  <Accordion title="Claude bills too much or can't select a newer model">
    You are probably running the old `@zed-industries/claude-agent-acp` bridge. See the warning in [Claude](#claude).
  </Accordion>
  <Accordion title="My new default from make pick-model isn't used">
    Restart Condor with `make restart`. If you already picked a model in Telegram or on the dashboard chat page, that choice wins over `CONDOR_DEFAULT_AGENT` for your chats.
  </Accordion>
  <Accordion title="No local model found">
    The local server is running but Condor couldn't find a model on it. Load a model, use an explicit key such as `ollama:qwen3:32b`, or set `CONDOR_DEFAULT_LOCAL_MODEL`.
  </Accordion>
</AccordionGroup>
