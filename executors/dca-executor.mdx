---
title: "DCA Executor"
description: "Build a position over a ladder of price levels, with one exit for the whole position"
---

The **DCA Executor** builds a position in steps. You give it a list of price levels and an amount for each, and it places one order per level. The exit (take profit, stop loss, trailing stop or time limit) is measured against the average entry price of everything that filled.

## Overview

| Property | Value |
|---|---|
| Markets | Spot and perpetuals |
| Condor tool | `create_dca_executor` |
| Exits | Take profit, stop loss, trailing stop, time limit, all on the average entry |
| `keep_position` | Not a config field. Only a stop parameter. |

## Create one from Condor

Agents and the Condor chat use the `create_dca_executor` tool:

```python
create_dca_executor(
    connector_name="binance",
    trading_pair="BTC-USDT",
    side=1,
    amounts_quote=[100, 100, 150],
    prices=[50000, 48000, 46000],
    take_profit=0.03,
    stop_loss=0.05,
    controller_id="my_agent.my_loop_1",
)
```

This buys $100 of BTC at 50,000, $100 at 48,000 and $150 at 46,000, closes everything at a 3% net profit on the average entry, and has a 5% stop loss. In an agent session, `controller_id` must be the session ID (see [Session IDs](/trading-agents/sessions#session-ids)).

<Note>
Amounts here are in the **quote** asset, unlike the position executor, whose `amount` is in the base asset. `amounts_quote` and `prices` are parallel lists: entry `i` is an order of `amounts_quote[i]` at `prices[i]`. Condor rejects lists of different lengths.
</Note>

### Parameters

| Parameter | Required | Meaning |
|---|---|---|
| `connector_name` | Yes | Exchange connector, such as `binance` or `binance_perpetual` |
| `trading_pair` | Yes | Trading pair, such as `BTC-USDT` |
| `side` | Yes | `1` BUY, `2` SELL |
| `amounts_quote` | Yes | Order size for each level, in quote |
| `prices` | Yes | Price for each level, in the order the levels are placed. For a buy ladder, list them from highest to lowest. |
| `mode` | No | `MAKER` (default) or `TAKER`. See [Modes](#modes). |
| `take_profit` | No | Close when the net profit on the average entry reaches this fraction (`0.03` is 3%) |
| `stop_loss` | No | Stop loss as a fraction. See [Exits](#exits). |
| `time_limit` | No | Close after this many seconds, counted from creation |
| `trailing_stop_activation_price` / `trailing_stop_trailing_delta` | No | Trailing stop, as profit fractions. Both are needed; one alone is dropped. Works as described for the [position executor](/executors/position-executor#trailing-stop). |
| `leverage` | No | Leverage for perpetuals. Default `1`. |
| `level_id`, `account_name`, `controller_id`, `save_as_default` | No | As for the other create tools. `controller_id` defaults to `main`; an agent passes its session ID. |

## Modes

Levels are placed one after another, in the order of `prices`. The next level is placed only after the previous level's order exists.

| Mode | Orders | When a level is placed |
|---|---|---|
| `MAKER` | Limit order at the level's price | Right away, one level after another |
| `TAKER` | Market order | When the price comes close to the level. By default that is between 0.01% below and 0.5% above the level price for a buy (mirrored for a sell). |

## Exits

| Exit | When it triggers | Close type |
|---|---|---|
| Take profit | Net profit on the average entry, after fees, rises above `take_profit` | `TAKE_PROFIT` |
| Stop loss, `MAKER` mode | Every level has filled **and** the net loss reaches `stop_loss` | `STOP_LOSS` |
| Stop loss, `TAKER` mode | The net loss in quote reaches `stop_loss` × the sum of `amounts_quote` | `STOP_LOSS` |
| Trailing stop | Net profit falls below the trailing trigger | `TRAILING_STOP` |
| Time limit | `time_limit` seconds have passed since creation | `TIME_LIMIT` |

Every exit cancels the unfilled levels and closes the filled amount with a market order.

<Warning>
In `MAKER` mode the stop loss does nothing until every level has filled. If the price falls part way through a buy ladder and keeps falling without reaching the last level, the stop loss never triggers. Use a `time_limit`, or `TAKER` mode, if you need a bound in that case.
</Warning>

## Via the API

Create the executor with `POST /executors/`. Unlike the position executor, the exits are top-level fields, not a `triple_barrier_config`.

```bash
curl -u YOUR_USERNAME:YOUR_PASSWORD -X POST http://localhost:8000/executors/ \
  -H "Content-Type: application/json" \
  -d '{
    "account_name": "master_account",
    "controller_id": "main",
    "executor_config": {
      "type": "dca_executor",
      "connector_name": "binance",
      "trading_pair": "BTC-USDT",
      "side": 1,
      "amounts_quote": ["100", "100", "150"],
      "prices": ["50000", "48000", "46000"],
      "take_profit": "0.03",
      "stop_loss": "0.05",
      "trailing_stop": {"activation_price": "0.02", "trailing_delta": "0.005"},
      "mode": "MAKER"
    }
  }'
```

The API also accepts `activation_bounds`, which the Condor tool doesn't expose: a list of two fractions that controls when a level is placed. In `TAKER` mode it replaces the default 0.01% and 0.5%.

## Close types

Besides the exits above, a DCA executor can end with:

| Close type | When |
|---|---|
| `EARLY_STOP` | You stopped it with `keep_position=false` |
| `POSITION_HOLD` | You stopped it with `keep_position=true` |
| `EXPIRED` | The time limit had already passed when it started |
| `FAILED` | A level was below the exchange's minimum order size or value, or orders kept failing |
| `INSUFFICIENT_BALANCE` | The account couldn't fund the ladder |

## Stopping early

Stop the executor with `stop_executor` or `POST /executors/{executor_id}/stop`:

- `keep_position=false` (the default) cancels unfilled levels and closes the filled amount at market.
- `keep_position=true` cancels unfilled levels and leaves the filled amount in the account.

<Warning>
A DCA executor stopped with `keep_position=true` ends as `POSITION_HOLD`, but the current Hummingbot API doesn't add its fills to the Position Hold, so they don't appear in `list_positions_held` or in an agent's held positions. Track or close that amount yourself.
</Warning>
